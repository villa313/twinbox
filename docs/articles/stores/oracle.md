# Oracle

`Twinbox.Oracle` stores the outbox and inbox with plain ADO.NET (`Oracle.ManagedDataAccess.Core`), for apps that use
Dapper or `OracleCommand`. For EF Core (`Oracle.EntityFrameworkCore`), use the [EF Core store](entity-framework-core.md).

## Setup

```csharp
builder.Services.AddTwinbox(twinbox => twinbox
    .UseOracle(connectionString)
    .UseKafka("localhost:9092")
    .Route<OrderPlaced>().To("orders"));
```

```csharp
twinbox.UseOracle(o =>
{
    o.ConnectionString = connectionString;
    o.Schema = "MESSAGING";   // an existing user; names are case-sensitive
});
```

## Options

| Option | Default | Description |
|---|---|---|
| `ConnectionString` | `null` | Connection string for the database holding the tables. |
| `ConnectionStringFactory` | `null` | Resolved per DI scope, e.g. to pick a tenant's database. Takes precedence over `ConnectionString`. |
| `Schema` | `null` | Owner of the tables; `null` uses the connected user's schema. The schema (user) must already exist. |
| `OutboxTable` | `"TwinboxOutbox"` | Outbox table name. |
| `InboxTable` | `"TwinboxInbox"` | Inbox table name. |
| `CreateSchemaIfMissing` | `true` | Create the tables and indexes at startup. It never creates the schema, since that takes DBA rights. |

Identifiers are quoted, so they are case-sensitive: the default tables are `"TwinboxOutbox"` and `"TwinboxInbox"`.

## Sending

```csharp
await using var connection = new OracleConnection(connectionString);
await connection.OpenAsync(ct);
await using var transaction = await connection.BeginTransactionAsync(ct);

await connection.ExecuteAsync("INSERT INTO ORDERS (ID, TOTAL) VALUES (:Id, :Total)", order, transaction);
outbox.Send(new OrderPlaced(order.Id));
await outbox.CommitAsync(transaction, ct);
```

## Handlers

```csharp
public class ShipOrder(HandlerTransaction tx) : IHandle<OrderPlaced>
{
    public Task HandleAsync(OrderPlaced message, MessageContext context, CancellationToken ct) =>
        tx.Connection.ExecuteAsync(
            "UPDATE ORDERS SET STATUS = 'SHIPPING' WHERE ID = :OrderId", message, tx.Transaction);
}
```

## Schema

Created at startup when missing (default names; "already exists" errors are ignored):

```sql
CREATE TABLE "TwinboxOutbox" (
    "Sequence" NUMBER(19) GENERATED BY DEFAULT ON NULL AS IDENTITY NOT NULL,
    "Id" RAW(16) NOT NULL,
    "MessageName" NVARCHAR2(256) NOT NULL,
    "Transport" NVARCHAR2(64) NOT NULL,
    "Destination" NVARCHAR2(256) NOT NULL,
    "PartitionKey" NVARCHAR2(256) NULL,
    "TenantId" NVARCHAR2(128) NULL,
    "Payload" BLOB NOT NULL,
    "ContentType" NVARCHAR2(128) NOT NULL,
    "Headers" NCLOB NOT NULL,
    "TraceParent" NVARCHAR2(64) NULL,
    "CreatedAt" TIMESTAMP(6) WITH TIME ZONE NOT NULL,
    "AvailableAt" TIMESTAMP(6) WITH TIME ZONE NOT NULL,
    "Attempts" NUMBER(10) NOT NULL,
    "Status" NUMBER(10) NOT NULL,
    "LeaseOwner" NVARCHAR2(256) NULL,
    "LeaseUntil" TIMESTAMP(6) WITH TIME ZONE NULL,
    "LastError" NVARCHAR2(2000) NULL,
    "SentAt" TIMESTAMP(6) WITH TIME ZONE NULL,
    CONSTRAINT "PK_TwinboxOutbox" PRIMARY KEY ("Sequence"));
CREATE UNIQUE INDEX "IX_TwinboxOutbox_Id" ON "TwinboxOutbox" ("Id");
CREATE INDEX "IX_TwinboxOutbox_Status_AvailableAt" ON "TwinboxOutbox" ("Status", "AvailableAt");
CREATE INDEX "IX_TwinboxOutbox_PartitionKey_Status" ON "TwinboxOutbox" ("PartitionKey", "Status");

CREATE TABLE "TwinboxInbox" (
    "MessageId" NVARCHAR2(256) NOT NULL,
    "Consumer" NVARCHAR2(256) NOT NULL,
    "Source" NVARCHAR2(256) NOT NULL,
    "ProcessedAt" TIMESTAMP(6) WITH TIME ZONE NOT NULL,
    CONSTRAINT "PK_TwinboxInbox" PRIMARY KEY ("MessageId", "Consumer"));
CREATE INDEX "IX_TwinboxInbox_ProcessedAt" ON "TwinboxInbox" ("ProcessedAt");
```

Column types match what Oracle's EF Core provider generates for `modelBuilder.AddTwinbox()`, so both stores can share
tables. Message ids are `RAW(16)` in .NET byte order.

## How it works

- **Claiming:** a PL/SQL block opens a cursor over due rows with `FOR UPDATE SKIP LOCKED`, fetches up to the batch
  size, leases them and returns them. (Oracle doesn't allow `FETCH FIRST` together with `FOR UPDATE`.)
- **Batches of statements** (inserts, completions) run as anonymous PL/SQL blocks, since Oracle runs one statement per
  command. Payloads are bound as LOBs, so they aren't limited to 32 KB.
- An empty string and `NULL` are the same in Oracle; Twinbox treats an empty partition key or tenant as none on every
  database for that reason.
